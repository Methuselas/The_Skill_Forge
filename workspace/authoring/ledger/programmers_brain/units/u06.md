## Notes

Placement: seven of the nine new objects went to a new topic,
`foundations/problem-solving`. The chapter is not about understanding code in
front of you — that is `code-comprehension`, where u01, u02, u04 and u05 sit — nor
about building knowledge for later, which is `foundations/deliberate-practice`
from u03. It is about choosing how to represent a problem you are about to solve,
which neither topic covers. This mirrors the u03 decision to open
`deliberate-practice` rather than force the material into an existing folder.

The two objects that went elsewhere went there deliberately.
`PAT_guard_against_an_outdated_mental_model_under_load` is a reading failure and
belongs beside `PAT_diagnose_source_of_code_confusion`, which sorts confusion into
missing knowledge, information, or processing power — this one names a fourth
cause those three miss, where the knowledge is present and the wrong copy was
retrieved. `DRILL_build_a_mental_model_flashcard_deck` went to
`deliberate-practice` beside the syntax deck.

That flashcard decision was the closest call in the unit. The method is identical
to `DRILL_practice_syntax_with_flashcards` — prompt side, answer side, spaced
practice, add on encounter — which argues for a variant. It was made a new drill
instead because the source states the split itself: "The goal of this second form
of flashcards is not to extend your knowledge of syntactic concepts but to extend
your vocabulary of mental models." A drill's `target_skill` is the thing being
built, and these differ. Doctrine's variant test is same decision, different
method; this is the mirror image, different decision on a shared method, which is
`new`. The two are cross-linked `related_to` so the pair stays findable.

The only variant absorbed lands on `PAT_externalize_intermediate_state_when_tracing`
(u01). Chapter 6 revisits externalization from a different direction — u01 writes
state down because working memory has run out, chapter 6 picks a constrained
notation because the constraint itself directs attention and helps the LTM surface
relevant memories. Same externalizing move, different reason it works, so it is a
variant on the method rather than a second foundation.

Two collisions were checked and left alone. `PAT_match_caller_mental_model`
(gcbc u01) shares the phrase "mental model" and nothing else — it is an API design
constraint about not surprising a caller, not a claim about how a reader reasons.
`PAT_verify_familiar_looking_code_tokens` (u01) is about long-term memory
supplying an expected token; the new outdated-model pattern is about long-term
memory supplying an expected *model*, which is a different granularity and a
different repair. Linked `related_to`.
