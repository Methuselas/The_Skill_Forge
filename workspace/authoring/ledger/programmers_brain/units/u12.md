## Notes

Placement: all four objects went to `foundations/code-quality`, beside
`PAT_evaluate_code_against_quality_goals` and the u09 code-smell pattern. This is
evaluation of code as an artefact, which is what that topic is for. Nothing went
to `working-practice` despite the shared framework with u11 — that topic is about
organising your own session, and this chapter is about a codebase's properties.

The main structural decision was **where to put the thirteen dimensions**. The
obvious reading makes the CDCB stance a new foundation pattern with the dimensions
in its Do section. It became a variant on `PAT_evaluate_code_against_quality_goals`
instead, because the decision is genuinely the same one — is this code any good —
approached by a different method and at a different scale. Doctrine's test is
same decision, different method, and that is exactly this. The catalogue then had
nowhere sensible to live inside a variant block, so it went to the drill, which is
where a thirteen-item checklist belongs anyway.

Each of the thirteen dimensions was raised as a candidate and rejected
individually rather than being waved through as one item. They are a catalogue the
source imports and extends, not thirteen separate skills, and the practitioner move
is running the list rather than knowing any single entry.

The source defect on Diffuseness in table 12.1 is recorded in the bounds note above
and in the pattern's Notes. It is worth flagging for anyone building on this
material: the table is the natural thing to quote from, and on that one row it is
wrong by its own chapter's account.
