## Notes

Placement: all three retained objects went to `foundations/code-comprehension`
alongside the u01, u02 and u04 material. Everything in this chapter concerns
understanding code in front of you rather than building knowledge for later, so
none of it belonged in `foundations/deliberate-practice`.

Three collisions were checked. `DRILL_annotate_a_dependency_graph_over_code` (u04)
took the focal-point version as a variant rather than a second drill, because the
source explicitly identifies the two as the same model at different settings.
`PAT_use_descriptive_names` (gcbc u05) took the Apps Hungarian constraint as a
variant on the same decision. `PAT_use_beacons_to_test_code_hypotheses` (u02) was
checked against the roles framework and left alone: beacons are cues a reader
collects to form a hypothesis, while roles are a classification applied to every
variable regardless of whether it hints at anything, so they are related rather
than competing — linked `related_to`.

Convention note: this unit's variants use the `VAR_` id prefix, matching the u03
and u04 work and the wider library, while `PAT_use_descriptive_names` already
carried `v_cognition_visually_distinct_identifiers` from u02 in the older `v_`
style. Both now sit in one file. Normalizing the remaining `v_*` ids across the
software-engineering package is a separate mechanical pass, not u05's business.

That pass was run on 2026-08-11. All eight `v_*` ids became `VAR_*` by prefix
swap, in the library cards and in the ledger rows that name them; the id above is
now `VAR_cognition_visually_distinct_identifiers`. Dated worklog narrative was
left as written — see `docs/domains/corpus/worklog.md` for the full mapping.
