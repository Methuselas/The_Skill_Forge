## Notes

Nineteen candidates, eight kept — the densest unit so far and the first where the
reject list is dominated by one identifiable block rather than scattered. Roughly a
third of this chapter, pp. 25-31, is written to help a programmer convince a
manager: the extended argument, the appeals to logic, analogy and data, the
boss-readiness test, the general anecdote, and the four responses to being ordered
to start coding. All of it is rejected under the u01 stance, and rejecting it is
not a loss — the underlying facts it marshals are retained as calibration inside
the cards that act on them.

**The tables were the unit.** This is the first chapter where text extraction alone
would have produced confidently wrong cards rather than merely thin ones. Table 3-1
extracted with its header row merged into the data, and Table 3-3/3-4's cost
columns detached from their rows. Two of the eight objects rest on numbers that are
only correct in the render. Treat any chapter with numeric tables as requiring a
render, not as a judgment call.

**Placement note.** `core/working-practice` now holds fifteen objects and has
become the de facto home for anything about how work is organized rather than how
code is written. That is defensible but it is drifting toward a catch-all. Watch it
through u04 and u05; if it keeps absorbing, the process material may want splitting
out from the cognitive-ergonomics material that Hermans put there.

**Forward pointers set here:** binding time and table-driven techniques to u05/u18;
the requirements and architecture checklists are reference lists that later chapters
do not supersede, so they stay in the ledger rather than becoming objects.
