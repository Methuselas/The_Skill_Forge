# Define Roles by Distinct World Interfaces

## Pattern Rule
**IF** character roles are supposed to create genuinely different professional identities
**THEN** give each role a distinct interface with world state—different verbs, access, legitimacy, resources, information, scale, or specialist authority—and build representative situations in which those interfaces can materially alter outcomes
**ELSE** treat the distinction as a skill emphasis or character concept rather than advertising it as a separate role architecture.

## Do
- State each role's privileged question or verb: who can command institutional resources, mobilize crowds, call on a community, control a technical environment, invoke legal authority, acquire restricted goods, or otherwise change the solution space.
- Measure role value by **cadence × consequence × exclusivity**, then check participation coverage and operator cost; a rare world-changing ability and a constant numerical bonus are not comparable by raw modifier size alone.
- Give the setting enough institutions, markets, crowds, networks, legal structures, technical systems, or relationships for the advertised role interfaces to exist naturally.
- Allow adjacent roles to attack the same problem through different methods, costs, risks, or scopes instead of making one role the mandatory key.
- Prefer specialist outputs that **change teammate decision surfaces**: open routes, suppress threats, create cover, expose information, protect allies, reposition a shared platform, or otherwise create better decisions for other players.
- When possible, let deep specialist control operate through a shared platform or shared objective rather than requiring the specialist to leave the group in an exclusive environment.
- Build **bidirectional access dependencies** where appropriate: let teammates alter the specialist's operating conditions through physical access, protection, credentials, positioning, signal quality, or other shared state, while the specialist's success opens routes or capabilities for them in return.
- Prefer privileged control over shared state to ownership of many independently resolving actors when both can express the same fantasy; a shared vehicle, sensor network, defense grid, or command interface can preserve specialist identity without multiplying one player's turns.
- Distinguish numerical privilege from agency privilege. A role may be distinctive because it acts more reliably on common verbs or because it can attempt verbs others cannot.
- Audit **interface breadth**, not only interface uniqueness. A role framed as owning one fictional domain can still become a generalist if that domain supplies reliable solutions to combat, reconnaissance, healing, mobility, stealth, social control, information, defense, and other roles' recurring problems. Price and constrain the breadth of consequential problem classes the interface can alter, not merely the number of named powers it contains.

## Don't
- Balance roles solely by comparing equal point costs, equal bonuses, or equal spotlight minutes.
- Give one role high-cadence benefits that self-activate in every important scene while another role's defining interface depends on rare referee charity, then call them equivalent.
- Protect a niche by making the rest of the party unable to participate in the shared objective.
- Assume a flavorful profession produces different play if the character proposes the same solutions as everyone else.

## Checklist
- Each role has at least one named world interface and a recurring reason to use it.
- Representative adventures expose those interfaces without requiring contrived token scenes.
- High-cadence, high-consequence, and exclusive role benefits have been compared separately.
- At least one shared problem admits more than one legitimate professional approach.
- At least one specialist success creates or changes a consequential decision for another role.
- At least one representative scene tests whether non-specialists can improve the specialist's access or operating conditions instead of merely waiting for the specialist's output.
- Removing a role changes the team's available methods without making the campaign structurally unplayable.
- A specialist's strongest mode has been checked for whether it still creates teammate decisions or instead isolates the specialist / multiplies their independent actors.
- A broad specialist interface has been tested against the recurring problem domains claimed by adjacent roles; no single role routinely owns several other roles' highest-value verbs without corresponding scarcity, risk, preparation, or opportunity cost.

## Notes
Strong role identity is often a relationship between the character and the world rather than a bundle of internal bonuses. A combat specialist may gain frequent numerical privilege, while a fixer-like character gains access, a corporate operator gains institutional leverage, or a network specialist gains exclusive control verbs. Those forms of power are not directly commensurable. Their practical value depends on how often the campaign exposes the relevant world interface and how consequential its use is. The strongest specialist architecture is often bidirectional: the specialist changes shared state for teammates, while teammates can materially change the specialist's access conditions, risk, or available targets. This keeps role privilege distinct without turning the role into a parallel game. Distinctive fiction does not by itself protect niches: one privileged interface can still be mechanically overbroad when it reliably reaches many independent problem classes. Role audits should therefore count the breadth of consequential verbs and scenario domains the interface can replace or transform, not only whether the interface has a unique name.
