# Design Shared Problems with Multiple Solution Interfaces

## Pattern Rule
**IF** a party contains specialists with different professional identities
**THEN** build shared objectives that expose several legitimate interfaces—technical, social, physical, informational, institutional, magical, criminal, or otherwise—so different specialists can alter the same situation through different methods
**ELSE** use narrower obstacles only when isolation itself is the intended experience and its participation cost is acceptable.

## Do
- Define the problem before defining the specialist solution: secure the building, find the illegal connection, acquire the target, expose the lie, escape the pursuit.
- Identify several ways the current roles could obtain information, access, leverage, position, or control around that problem.
- Let methods differ in speed, risk, legality, cost, reliability, visibility, or collateral consequences rather than making every route mechanically identical.
- Let legwork and preparation expose dependencies that can remove, reroute, or transform a later obstacle rather than merely adding a modifier to the same required sequence.
- Allow one role's success to create better decisions for others: cameras disabled, credentials acquired, witnesses convinced, guards redirected, routes opened.
- Preserve the possibility of improvised approaches not listed in the scenario when they engage the same world state coherently.

## Don't
- Design one locked computer for the hacker, one wounded NPC for the medic, and one guard for the fighter and call that integrated specialist play.
- Make the specialist route the only route unless the campaign has guaranteed access to that role and the hard gate is intentional.
- Give every role a token roll that does not change access, risk, information, or outcome.

## Checklist
- The objective can be stated without naming a required skill or role.
- At least three plausible interfaces with the problem exist when the party composition supports them.
- Methods produce different costs, risks, information, or downstream state.
- Success by one specialist can change another player's decision environment.
- The scenario remains playable when one expected specialty is absent, unless absence is intentionally part of the challenge.

## Notes
Specialist identity integrates best around one shared problem, not a sequence of isolated specialist rooms. A technical expert, network operator, fixer, investigator, infiltrator, or combatant can all contribute to the same objective when the world exposes several causal handles. This increases participation coverage while preserving meaningful asymmetry.
