# Choose Between an Original TTRPG and an Existing System

## Pattern Rule
**IF** a TTRPG concept is ready to choose its rules foundation
**THEN** use an existing permitted system unless the intended experience depends on a rules approach that system cannot provide.
**ELSE** postpone the choice and test the experience in a short adventure or prototype before committing to a rules foundation.

## Do
- Identify the distinctive experience, setting, or mechanical interaction the project must deliver.
- Compare that requirement with what a candidate system already supports, including the conventions its players recognize.
- For an existing system, learn its audience, reproduce the features that make it recognizable, and verify the creator's permission before writing distributable material.
- For an original system, account for the added work of testing rules, explaining them to new players, building an audience, and supplying any unusual play materials.

## Don't
- Build a new rules system merely because the setting or adventure idea feels original.
- Treat an open or third-party license as permission to use a publisher's identity, protected material, or rules without reading the applicable terms.

## Checklist
- The project states why an existing system can or cannot deliver its central experience.
- Any planned system adaptation has a verified permission path before publication work begins.
- An original-system choice includes a credible plan for playtesting and for any nonstandard materials players need.

## Notes
An existing system contributes tested rules and an audience that already knows what to expect, but it also constrains the work to that game's identity and permissions. An original system gives the designer fuller control, yet its novelty has to earn the extra burden it creates for players and for the project.
