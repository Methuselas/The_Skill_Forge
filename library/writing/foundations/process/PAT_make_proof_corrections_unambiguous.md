# Make Proof Corrections Unambiguous

## Pattern Rule
**IF** corrections must be communicated on a formatted proof or shared manuscript
**THEN** anchor each instruction to the exact affected matter, name the operation and replacement completely, and state whether the corrected work needs another proof

## Do
- Use the publisher's, venue's, or team's accepted annotation system rather than assuming one symbol set is universal.
- Mark the precise character, word, line, space, or block affected and place the instruction where another person can find it without inference.
- Supply replacement text, order, distance, alignment, or spacing measurements whenever the operation alone would leave the result uncertain.
- Distinguish deletion, substitution, insertion, transposition, spacing, and layout changes so the implementer does not have to diagnose the problem again.
- Review the implemented result and request another proof when corrections can alter line flow, pagination, alignment, or neighboring matter.

## Don't
- Circle a broad area and write a vague instruction such as `fix`, `awkward`, or `spacing` with no intended result.
- Combine several unrelated corrections under one mark when their locations or operations differ.
- Import an unfamiliar legacy mark into a workflow whose participants cannot decode it.
- Approve the work for release before confirming that requested changes were made without introducing new errors.

## Checklist
- Every instruction resolves to one exact locus and one intended operation.
- Inserted or substituted matter is supplied in full and in the correct order.
- Quantified layout changes include the needed direction or measure.
- Unchanged matter and completed corrections cannot be mistaken for open queries.
- The final disposition clearly requests correction, another proof, or release.

## Notes
Proof annotation is a communication system, not a test of symbol memorization. Paper marks, comments, and tracked changes use different surfaces, but all reliable systems coordinate two things: the exact matter being changed and an instruction that determines the resulting state. Corrections that affect layout require another inspection because fixing the named defect can move or damage neighboring text.
