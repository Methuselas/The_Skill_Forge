# Draft and Finalize Selection-Criteria Responses

## Objective
Produce a complete, independently assessable set of selection-criteria responses whose claims, examples, structure, and delivery form satisfy the current role's evaluation contract.

## Steps / Flow
1. **Freeze the response contract.** Gather the advertisement, position or role description, applicant kit, agency guidance, named criteria or capabilities, duty statement, required response location, limits, headings, identifiers, deadline, and current instructions. Resolve any conflict through the named contact route before drafting; local convention never overrides the live application.
2. **Establish the full criterion set.** Preserve the supplied order and distinguish essential, desirable, mandatory, and capability-based items only where the employer does. Include every descriptor that defines a capability. If the application places responses in a cover letter, form, or statement of claims, keep that container as a constraint rather than changing the evidence task.
3. **Decode before selecting stories.** Activate `writing_decode_selection_criteria_into_evidence_obligations` for every criterion. Create an evidence map that records the proof strength, each subject and compound clause, possible examples, and gaps. Do not advance while an obligation remains invisible.
4. **Pass the evidence gate.** Verify mandatory conditions directly. Match each other obligation with the strongest truthful qualification, acquired knowledge, transferable action, direct performance, or achievement available. An unsupported mandatory or essential requirement blocks a claim; seek clarification, identify an honest limitation, or reconsider the application instead of fabricating evidence. Ability or capacity may take a transferable-evidence branch, but demonstrated or proven performance may not.
5. **Draft one assessable case at a time.** Activate `writing_answer_each_selection_criterion_as_a_standalone_evidence_case`. Start with a calibrated claim, then use relevant context, candidate action, and result. For knowledge or understanding, include acquisition, application, significance, and practical consequences in the combination the wording requires. A failed subrequirement check returns to the evidence map rather than being hidden by smoother prose.
6. **Audit the set as an unfamiliar panel would.** Confirm that every response stands alone, internal terminology is explained, candidate ownership is explicit, and no panel knowledge is assumed. Check the set for repeated anecdotes that leave different criteria unproved, contradictions with the résumé or form, and claims whose strength changes from one component to another. Reconcile every factual correction across the package.
7. **Fit the instructed container.** Apply the required headings, numbering, role and vacancy identifiers, filename, field placement, and word or file limits. For form fields, activate `writing_answer_application_forms_as_complete_standalone_evidence`; for an online system, also activate `writing_preserve_online_application_work_across_form_constraints`. Preserve action and result when compressing, and verify the displayed or reopened final text.
8. **Close and hand off the response set.** Activate `writing_proofread_application_materials_with_independent_passes` after substantive edits stop. Compare the finished set with the frozen criterion list and evidence map one final time. Completion requires every required criterion to be present, proportionately supported, readable within its instructed container, consistent with the other documents, and ready for the enclosing multi-part application protocol.

## Notes
The dependency order matters: formatting a response before decoding its obligations can polish an incomplete answer, while drafting before testing evidence strength invites inflated claims. The workflow stops at a trustworthy response set; the enclosing application protocol remains responsible for assembling, transmitting, and preserving the whole submission.
